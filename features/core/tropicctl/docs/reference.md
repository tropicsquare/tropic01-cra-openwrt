# tropicctl reference

_Generated by `tropicctl help --format markdown`; do not edit by hand._

Usage: `tropicctl [global options] <area> <verb> [arguments]`

## Safety classes

| Class | Meaning |
|---|---|
| R read-only | changes nothing on the chip |
| W reversible write | can be undone by another command (an R-MEM slot, an ECC key) |
| I irreversible | cannot be undone; needs a named --yes-... flag |
| H hazardous | can leave the chip unusable if done wrong; needs a named --yes-... flag |

## Global options

| Option | Meaning |
|---|---|
| `--spi-dev PATH` | SPI device (default /dev/spidev2.0, or $TROPICCTL_SPI_DEV) |
| `--gpio-dev PATH` | GPIO chip (default /dev/gpiochip0) |
| `--cs-pin N` | chip-select GPIO line (default 25) |
| `--spi-speed HZ` | SPI clock (default 1000000) |
| `--key SOURCE` | pairing key: auto (default), shared, unit, file:PATH:SLOT, pin |
| `--pin-file FILE, --pin-stdin` | where a PIN comes from (never the command line); otherwise a terminal prompt |
| `--json` | machine-readable output on stdout; errors as a JSON object on stderr |
| `-q, -v` | quiet / verbose notices on stderr |
| `--lock-timeout SEC` | how long to wait for the chip lock (default 10) |
| `--dry-run` | check everything read-only, say what would be written, write nothing |
| `--no-lock` | do not take the chip lock (tests and debugging only) |
| `--version, -h` | print the version / this help |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | internal error (a bug) |
| 2 | usage error (bad arguments) |
| 3 | chip unreachable or busy (SPI, GPIO, lock timeout) |
| 4 | secure session failed (no usable pairing key, key refused) |
| 5 | access denied by the chip's access rights |
| 6 | slot empty or object not found |
| 7 | slot already written |
| 8 | verification failed (read-back mismatch) |
| 9 | refused by a safety rule (missing confirmation flag, forbidden target) |
| 10 | the chip reported another error |

## Commands

### info

#### `info chip `

Class **R**. Print the chip identification

Reads CHIP_ID. No secure session is needed. The text is the layout `lt-util -i` printed; with --json every CHIP_ID group is a hex string, as libtropic defines the groups, without interpretation.

#### `info fw `

Class **R**. Print the RISC-V and SPECT firmware version bytes

Prints the version bytes as the chip reports them and the version they stand for, read as libtropic reads them (byte 3 . byte 2 . byte 1; byte 0 is not part of the version). No secure session is needed.

#### `info mode `

Class **R**. Print the chip mode (application or maintenance)

No secure session is needed. Most commands need the chip in application mode.

#### `info cert [--out-dir DIR]`

Class **R**. List the chip's certificate store

Prints the length of each of the four store certificates; with --out-dir each is written as certN.der. Verifying the chain against Tropic Square's root is not done by this command. No secure session is needed.

### rng

#### `rng get <count> [--out FILE|-] [--hex]`

Class **R**. Random bytes from the chip (1 to 255)

Without --out the bytes are printed as hex. With --out FILE (or - for stdout) they are written raw. Needs a secure session.

### mem

#### `mem list [--range A-B]`

Class **R**. Which R-MEM slots hold data, and how much

Reads each slot in the range (default 0-511; every slot is one chip command, so the full range takes a while) and lists the populated ones.

#### `mem read <slot> [--out FILE|-]`

Class **R**. Read an R-MEM slot (0-511)

Without --out the content is printed as hex; with --out it is written raw. An empty slot is exit code 6.

#### `mem write <slot> --in FILE|- [--replace]`

Class **W**. Write an R-MEM slot (1 to 475 bytes)

Refuses an occupied slot unless --replace is given (then the slot is erased first). The slot is read back and compared; a mismatch is exit code 8. With --dry-run nothing is written.

#### `mem erase <slot>`

Class **W**. Erase an R-MEM slot

Erases the slot and checks that it reads empty. Erasing an empty slot is not an error. With --dry-run nothing is written.

### ecc

#### `ecc list `

Class **R**. The 32 ECC key slots: empty, or curve and origin

Origin is generated (made inside the chip, never exported) or stored (a key that was loaded from outside, which the chip cannot vouch for).

#### `ecc generate <slot> --curve p256|ed25519 [--replace --yes-erase-ecc-key]`

Class **W**. Generate a key inside the chip

The private key never leaves the chip. An occupied slot is refused; --replace erases it first and needs --yes-erase-ecc-key, because the old key is lost for good. The key is read back and checked.

#### `ecc store <slot> --curve p256|ed25519 --in FILE [--replace --yes-erase-ecc-key]`

Class **W**. Store a private key from a file

The file holds the 32-byte private key. The key's origin is then "stored", not "generated", which matters for trust. Rules for an occupied slot as for generate.

#### `ecc pub <slot> [--out FILE|-] [--format raw|pem]`

Class **R**. The public key of a slot

raw is 64 bytes X||Y for P-256 and 32 bytes for Ed25519; pem is a SubjectPublicKeyInfo. Without --out it is printed.

#### `ecc erase <slot> --yes-erase-ecc-key`

Class **I**. Erase an ECC key

The key is destroyed for good (a generated key cannot be recreated). Needs --yes-erase-ecc-key; checks the slot reads empty afterwards. Erasing an empty slot is not an error.

#### `ecc sign <slot> --in FILE [--out FILE|-] [--alg ecdsa|eddsa] [--digest] [--der]`

Class **R**. Sign with a key in the chip

ECDSA signs a 32-byte hash: without --digest the input is hashed with SHA-256, with --digest it must be exactly 32 bytes. EdDSA signs the message (up to 4095 bytes). The algorithm follows the slot's curve; a mismatch is refused. The signature is 64 raw bytes (r||s), or DER with --der (ECDSA).

### pairing

#### `pairing list `

Class **R**. State of the four pairing slots

Each slot is populated, empty or invalidated. Reading the slots needs a session; with the shared key this works unless the chip's access rights say otherwise.

#### `pairing read <slot> [--out FILE]`

Class **R**. Read the public pairing key of a slot (0-3)

Prints the 32-byte public key as hex, or writes it raw with --out. An empty or invalidated slot is exit code 6.

#### `pairing write <slot> --in FILE --yes-write-pairing-slot`

Class **I**. Write a public pairing key into an empty slot (1-3)

IRREVERSIBLE: a pairing slot is written once. The file holds the 32-byte public key. Slot 0 (the shared engineering key) is refused. The slot must read empty first; it is read back and compared afterwards, because older firmware can fail silently. With --dry-run the checks run and nothing is written.

#### `pairing invalidate <slot> --yes-invalidate-pairing-slot [--yes-invalidate-shared-key]`

Class **I**. Invalidate a pairing slot

IRREVERSIBLE. The slot being invalidated must not be the key that opened this session. Slot 0 also needs --yes-invalidate-shared-key and a session opened with another, working pairing key, so that the chip stays reachable.

### config

#### `config dump [--decode]`

Class **R**. Every R-config and I-config object as raw words

Prints "R NAME 0xVALUE" lines for the reconfigurable objects and "I NAME 0xVALUE" lines for the one-way objects. --decode adds, for each access object, which pairing keys may use the command on which group of targets.

#### `config get <name>`

Class **R**. One configuration object (the TR01_CFG_ prefix may be left out)

Prints the R-config and the I-config word of the object.

#### `config diff --in FILE [--check]`

Class **R**. Compare the chip's R-config with a file

Lists each differing object with which pairing keys would gain or lose access. With --check the exit code is 8 if anything differs.

#### `config restrict-shared --unit-slot N [--out FILE|-]`

Class **R**. Build a config file that takes the shared key's rights away

Reads the chip's current R-config and writes a copy with pairing key 0 (the shared engineering key) removed from every access object except PING. Refuses unless pairing slot N holds a key and has the right to read and rewrite the configuration, so the restriction can be undone. Changes nothing on the chip; apply the file with config rewrite.

#### `config rewrite --in FILE --yes-rewrite-r-config [--backup FILE] [--include-non-access]`

Class **H**. Rewrite the R-config from a file

HAZARDOUS. Validates the file, saves the current R-config to a backup, ERASES then writes the R-config, and reads it back. Writing without erasing can put the chip into permanent Alarm Mode, so this is the only way the tool writes it. Refuses a file that would take the session key's right to read or rewrite the configuration, and a file that changes objects that are not access rights unless --include-non-access is given. If the write fails after the erase the message says so and names the backup.

#### `config restore --in BACKUP --yes-rewrite-r-config`

Class **H**. Write a saved R-config back

The same safe sequence as rewrite, for a backup file that config rewrite saved.

#### `config burn <name> <bit> --yes-burn-i-config-bit`

Class **I**. Clear one I-config bit (one-way)

IRREVERSIBLE: an I-config bit only goes from 1 to 0. Refused unless the CPU firmware is 2.0.0 or newer (older firmware can fail the write silently); the bit is read back afterwards.

### mnd

#### `mnd setup --state FILE --out KEYFILE --yes-setup-mnd [--slots N] [--base-slot B] [--add-file F] [--replace]`

Class **I**. Set a new PIN (MAC-and-Destroy)

Runs the new-PIN procedure of Tropic Square's application note ODN_TR01_app_002: initialises N chip slots (default 5) from the base slot, writes the host state (needs no protection) to --state and the released 32-byte key to --out. The PIN (4 to 8 characters) comes from --pin-file, --pin-stdin or a terminal prompt, never the command line.

#### `mnd check --state FILE --out KEYFILE [--add-file F]`

Class **W**. Check a PIN and release the key

A wrong PIN destroys one chip slot and uses one attempt; when none remain the key can never be released. The decremented attempt count is saved before the chip is touched.

#### `mnd status --state FILE`

Class **R**. Attempts left according to the host state

Reads only the state file (no chip access). The chip's own slots are authoritative.

#### `mnd seal --key-file K --in FILE --out FILE`

Class **R**. Encrypt a file with a released key (AES-256-GCM)

For the PIN-protected pairing key: seals the 32-byte private key under the key mnd check released. Host only.

#### `mnd unseal --key-file K --in FILE --out FILE`

Class **R**. Decrypt a sealed file

The reverse of seal. Exit code 8 if the key is wrong or the file is damaged. Host only.

### counter

#### `counter get <n>`

Class **R**. Read a monotonic counter (0-15)

An uninitialised counter is exit code 6.

#### `counter init <n> <value> --yes-init-counter`

Class **I**. Set a monotonic counter (0 to 4294967294)

Per libtropic's functional test a counter can be initialised again, so rollback protection holds only after the chip's access rights remove the init right from every key. Read back afterwards.

#### `counter update <n> --yes-update-counter`

Class **I**. Decrement a monotonic counter by one

Per libtropic's functional test an update decrements by one and fails at zero (refused here before it is tried).

### session

#### `session test `

Class **R**. Open and close a secure session; say which key was used

Reports the pairing key and slot that opened the session. Exit code 4 if no key works. With --key pin the PIN-protected key is used (PIN from --pin-file, --pin-stdin or the terminal).
